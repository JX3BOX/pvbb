# 团队首页设计与开发基线

> 状态：已落地的团队首页设计基线  
> 适用项目：`pvbb`  
> 目标页面：`/team/`  
> 参考实现：`pvx` 的 `/pvg/manufacture`  
> 参考仓库版本：`pvx@ae17a1f`  
> 整理日期：2026-07-28

## 1. 文档目的

本文档用于记录当前团队首页已经落地的页面结构、视觉语言、交互规则、响应式策略和验收标准，并作为后续团队模块优化的设计基线。

本文档是开发约束，不是要求照搬“技艺助手”的具体业务布局。团队首页应复用 PVX 的设计体系，同时保持团队模块“浏览、发现、管理和招募”的业务属性。

## 2. 当前改造范围

### 2.1 本期目标

- 优化 `/team/` 首页的信息层级与视觉表现。
- 建立团队模块可继续复用的设计令牌和基础展示组件。
- 保留现有团队业务接口、路由和主要数据逻辑。
- 优先复用现有团队列表、活动列表等业务组件，逐步替换旧样式。
- 同时考虑桌面、平板和移动端，不以桌面页面简单压缩作为最终移动方案。

### 2.2 当前入口

- 构建入口：`src/pages/team/index.js`
- 页面外壳：`src/pages/team/App.vue`
- 路由配置：`src/pages/team/router.js`
- 状态管理：`src/pages/team/store.js`
- 当前首页路由组件：`src/views/team/org/ListOrg.vue`
- 当前团队列表组件：`src/components/team/org/team_list.vue`
- 当前活动列表组件：`src/components/team/raid/RaidList.vue`
- 当前侧边导航：`src/components/team/widget/Nav2.vue`

### 2.3 非本期目标

- 不在首页视觉改造中同步重写全部团队 API。
- 不在没有迁移验证的情况下删除历史文件。
- 不直接从相邻的 `pvx` 仓库跨项目导入组件或样式。
- 不复制 manufacture 的配方、购物车、价格等业务结构。

### 2.4 当前落地结果

当前 `/team/` 已完成以下改造：

- 首页使用独立的双栏工作区，不显示旧版面包屑和全局旧侧栏。
- 桌面端左侧使用 `280px` 的个人工作台，上组承载“团队广场 / 团队活动”，下组承载“团队管理 / 我的团队 / 我的角色”。
- 个人工作台由团队模块共享页面壳承载，在团队广场与 `/my/org/:id` 团队工作台之间切换时保持常驻。
- 团队工作台通过 `mode=manage|member` 明确区分管理视图与成员视图，同一团队可从不同身份入口进入。
- 页面壳不再设置桌面端最大宽度；左侧仅保留少量页面留白，右侧内容铺满剩余空间。
- 页面右侧顶部使用 Hero 区表达“团队平台”身份，并提供“创建团队”“使用指南”入口。
- 服务器选择、团队搜索和类型筛选整合在同一工具面板中，创建入口提升到 Hero 区。
- 团队列表在桌面端使用双列轻量卡片，在窄屏下切换为单列。
- 团队卡片按照名称、认证、服务器、团长、类型和公告的优先级组织信息。
- 筛选条件统一为可换行的标签式复选控件，并支持一键清空。
- 列表和分页均提供等尺寸骨架屏，加载和翻页时保持页面高度稳定。
- 失效团队 Logo 自动回退到默认 Logo。
- 分页器使用与卡片一致的圆角、颜色和交互状态。
- 应用等待首个路由解析完成后再挂载，避免刷新时闪现旧版内页布局。

### 3.2 可复用的核心方法

PVX manufacture 的改造方式是：

1. 用统一页面壳控制背景、宽度和页面留白。
2. 用统一表面组件表达 Hero、工具栏和内容区。
3. 用设计令牌统一颜色、圆角、间距、阴影和动效。
4. 保留原有业务组件，通过页面级主题样式渐进改造。
5. 使用清晰的页面命名空间，避免新样式污染未改造页面。
6. 桌面端按断点逐步降级，移动端在必要时使用独立的信息结构。

团队首页应采用相同的渐进式改造策略。

## 4. 设计原则

### 4.1 整体气质

设计关键词：

- 现代
- 轻量
- 清晰
- 工具型工作台
- 业务信息优先
- 克制的品牌表达

页面不应表现为传统后台表格，也不应变成大量悬浮卡片的门户首页。

### 4.2 信息分层

使用四级结构：

1. **个人工作台（Personal Workspace）**：承载团队导航和真实的“我的团队”快捷列表。
2. **页面概览区（Hero）**：说明页面身份，承载最高优先级操作。
3. **筛选工具栏（Toolbar）**：承载服务器、搜索和筛选。
4. **内容工作区（Workspace）**：承载团队列表、活动与招募信息。

### 4.3 卡片使用

- 只在业务大区块使用大圆角白色表面。
- 卡片内部优先使用列表、分隔线和浅色块。
- 避免超过两层的“卡片套卡片”。
- 阴影只用于区分背景，不制造强烈悬浮感。
- 交互卡片悬停最多上移 `2px`。

### 4.4 业务色

- 紫蓝色只表达全局品牌操作和选中状态。
- 门派、阵营、装备品级、认证和业务状态保留其语义色。
- 危险操作只使用红色，成功状态只使用绿色，警告状态只使用橙黄色。

### 5.2 圆角

| 层级 | 值 |
| --- | --- |
| 大面板 | `24px` |
| 业务卡片 | `20px` |
| 控件和内嵌面板 | `16px` |
| 小控件和列表项 | `10px` |
| 标签 | `9999px` |

### 5.3 间距

统一使用以下间距序列：

```text
8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px
```

默认规则：

- 页面区块间距：`20px`
- 卡片标准内边距：`24px`
- 移动端卡片内边距：`16px`
- 控件间距：`8px` 或 `12px`
- 页面桌面留白：`32px`
- 页面平板留白：`24px`
- 页面移动留白：`16px`

### 5.4 阴影和焦点

```less
@team-shadow-xs: 0 1px 2px rgba(15, 23, 42, 0.05);
@team-shadow-sm: 0 3px 8px rgba(15, 23, 42, 0.06);
@team-shadow-hover: 0 12px 24px rgba(15, 23, 42, 0.1);
@team-shadow-focus: 0 0 0 3px rgba(91, 92, 245, 0.16);
```

所有键盘可操作控件必须有清晰的 `:focus-visible` 状态。

### 5.5 动效

```less
@team-duration-fast: 150ms;
@team-duration-normal: 200ms;
@team-duration-slow: 300ms;
@team-ease-standard: cubic-bezier(0.2, 0, 0, 1);
```

- 常规颜色切换使用 `150ms`。
- 卡片和面板交互使用 `200ms`。
- 不使用大幅位移、弹跳或持续动画干扰内容浏览。

## 6. 首页目标结构

### 6.1 页面概览区

建议内容：

- 团队平台图标
- 标题“团队平台”
- 一句简短说明
- 服务器选择
- 主要操作“创建团队”
- 可选次要操作“我的团队”

视觉要求：

- 使用白色大圆角表面。
- 右上角使用低透明度紫色径向渐变。
- 图标容器为 `44 × 44px`、`14px` 圆角、深色渐变背景。
- 标题使用 `24px / 600`。
- 描述使用 `12–14px / 600` 的弱化文字。
- 主要操作使用紫蓝色实心按钮。
- 次要操作使用白底描边按钮。

### 6.2 筛选工具栏

建议频道：

- 团队广场
- 我的团队
- 活动大厅
- 招募信息

最终频道是否同时上线由产品需求决定，但工具栏结构应支持这些频道。

工具栏要求：

- 桌面端可吸顶。
- 白色半透明背景并使用轻微模糊。
- 最小高度约 `68px`。
- 标签高 `40px`，最小宽度约 `82px`。
- 当前标签为紫蓝底白字。
- 搜索框占据剩余宽度。
- 服务器、客户端等筛选项不要分散到多个无关联区域。

当前实现补充：

- 第一行放置服务器选择和团队搜索，搜索框占据剩余空间。
- 第二行放置“只看认证”和团队类型筛选。
- 筛选项使用 `32px` 高的轻量标签，选中后使用主色浅背景与勾选状态。
- 筛选项允许自动换行；存在选中条件时显示“清空”操作。
- 不额外显示“筛选”标题，减少重复信息和视觉噪音。

### 6.3 个人工作台与内容工作区

桌面端当前结构：

```text
280px + minmax(0, 1fr)
```

左侧个人工作台：

- 团队广场和公开团队活动导航。
- 团队管理、我的团队和外链我的角色组成个人工作区导航。
- “我管理的团队”与“我的团队”是两个可独立展开的身份分组。
- 两组均展示团队 Logo、名称和服务器；管理分组额外标记自己创建的团队。
- 同一团队可以同时出现在两个分组中，点击时分别进入管理视图或成员视图。
- 未登录、加载、失败和无团队状态。
- 团队列表在展开后使用有上限的内部滚动，避免多团队账号把侧栏无限撑长。
- 当前团队仅在对应身份分组中显示选中状态。
- 团队切换统一通过常驻列表完成，Hero 只保留必要的身份切换和团队主页入口。

右侧主内容：

- 团队平台 Hero。
- 服务器、搜索和类型筛选。
- 团队列表、加载、空状态和分页。

`1280px` 及以下团队卡片切换为单列；`1100px` 及以下个人工作台转为顶部双区布局；`820px` 及以下主内容优先显示，个人工作台移动到列表之后。

### 6.4 团队工作台身份模式

管理视图只承载团队治理能力，并按当前账号的权限展示：

- 成员管理
- 战绩管理
- 视频管理
- 快照管理
- DKP 管理
- RAID 管理
- 团队档案（仅创建者）

成员视图只承载当前用户在所选团队中的个人信息和参与记录：

- 我的角色
- 我的战绩
- 我的 DKP
- 参与的 RAID

管理视图不展示“我的角色”等个人 Tab；成员视图也不展示编辑团队、前往认证或其他管理入口。创建者和管理员仍可通过 Hero 的身份切换按钮回到另一种视图。历史 Tab 链接继续兼容，并在进入后归一化为新的 `mode` 与 `tab` 参数。

### 6.5 团队卡片

当前团队卡片采用以下规则：

- 桌面端双列排列，卡片最小高度为 `132px`。
- Logo 使用 `68 × 68px`、`18px` 圆角；窄屏下缩小为 `56 × 56px`。
- 团名使用 `16px / 600`，认证图标与文字进行视觉中心校正。
- 服务器、团长和类型使用紧凑的弱标签表达，不与标题争夺注意力。
- 公告与主要元信息之间使用弱分隔线，内容单行截断，并通过 `title` 提供完整文本。
- 整张卡片可点击，因此不再额外展示右侧箭头。
- 悬停状态只使用边框、阴影和 `2px` 上移，不使用大幅动画。
- Logo 字段存在但图片加载失败时，自动替换为默认团队 Logo。

### 6.6 加载与分页

- 首次加载直接显示团队卡片骨架，不渲染历史模拟数据。
- 骨架结构对应 Logo、标题、元信息和公告，避免内容加载前后发生明显跳动。
- 桌面端骨架保持双列，`820px` 以下切换为单列。
- 分页加载时保留 `58px` 高的分页骨架；移动端保留 `50px`。
- 分页器和分页骨架宽度、圆角与内边距保持接近，避免 `CommonFooter` 上下闪动。
- 骨架扫光动画遵循 `prefers-reduced-motion`。

### 7.1 组件职责

`TeamPageShell`

- 负责页面背景、最大宽度、水平和垂直留白。
- 不包含具体团队业务。

`TeamSurface`

- 负责白色表面、边框、圆角、阴影和内边距。
- 通过 props 控制标签、圆角、内边距和是否可交互。

`TeamSectionHeader`

- 负责图标、标题、说明和右侧操作插槽。
- 标题层级必须可以配置为 `h1` 至 `h4`。

`TeamToolbar`

- 负责筛选区的排列、换行、移动端横向滚动和操作插槽。

`TeamEmptyState`

- 统一无团队、无活动、无搜索结果、未登录等状态。
- 支持标题、说明、图标/插画和操作插槽。

### 7.2 命名空间

首页根节点使用：

```text

```

推荐 BEM 风格：

```text

.m-team-home__toolbar
.m-team-home__workspace
.m-team-home__list
.m-team-home__aside
.u-team-home-tab
```

新主题样式必须限制在 `.p-team-home` 下，避免影响团队模块其他旧页面。

## 8. 渐进式迁移策略

### 阶段一：页面骨架

- 新增设计令牌和基础展示组件。
- 重组首页为 Hero、Toolbar、Workspace。
- 保留现有 `team_list.vue` 的请求和数据结构。
- 保留 `/team/` 当前路由，避免链接兼容问题。

### 阶段二：团队列表

- 将旧团队列表视觉迁移到新主题。
- 统一图片比例、标题、标签、服务器、阵营、认证和人数信息。
- 补全加载、空状态和错误状态。
- 减少列表项内部的多层边框。

### 阶段三：辅助信息

- 接入我的团队、待处理项和活动摘要。
- 明确登录前后的展示差异。
- 对右侧内容进行内部滚动或自适应处理，避免撑高主列表。

### 阶段四：移动端

- 调整信息优先级，不机械堆叠桌面双栏。
- 频道支持横向滚动。
- 主要操作保持易触达。
- 验证安全区域和底部固定操作是否必要。

### 阶段五：清理

- 在确认新首页稳定后，检查旧首页和旧样式引用。
- 只有确认无路由、无 import、无动态引用后才删除历史文件。

## 9. 响应式基线

| 断点 | 行为 |
| --- | --- |
| `> 820px` | 团队卡片双列，Hero 标题与快捷入口同排 |
| `≤ 820px` | 团队卡片切换单列，Hero 快捷入口换行 |
| `≤ 560px` | 页面使用 `16px` 左右留白，工具栏改为网格布局 |
| `≤ 560px` | 筛选标签使用三列网格，隐藏分页总数与跳转输入 |

首页实现不能只在一个桌面宽度下验收。

## 10. 交互与可访问性

- 频道切换使用原生 `button`，并提供 `aria-pressed`。
- 频道容器使用 `nav` 和明确的 `aria-label`。
- 页面只能有一个 `h1`。
- 业务区块按顺序使用 `h2`、`h3`。
- 图标按钮必须提供可访问名称或 tooltip。
- 颜色不能作为认证、状态、阵营等信息的唯一表达方式。
- 搜索和筛选需要支持键盘操作。
- 加载状态不能造成大幅布局抖动。
- 空状态必须告诉用户原因，并在可恢复时提供下一步操作。

## 11. 开发约束

- 页面和组件使用 Vue 3 Options API。
- 可使用 Tailwind CSS 实现结构型样式。
- 页面主题、复杂状态和设计令牌使用 Less。
- API 调用继续放在 `src/service/team/`。
- 跨组件共享状态继续通过现有 Vuex 或明确的 props/events 管理。
- 不在展示组件中直接拼接 API 地址。
- 不直接复制 PVX 的业务组件，只借鉴设计组件模式。
- 不为了视觉改造改变现有接口字段含义。
- 不在首页主题中使用无命名空间的全局选择器。

## 12. 验收标准

### 12.1 视觉

- 页面背景、表面、文字、主色符合本设计令牌。
- 页面主体最大宽度和留白统一。
- Hero、Toolbar、Workspace 层级明确。
- 卡片圆角、间距、边框和阴影一致。
- 页面中不存在明显的旧式厚边框、强阴影和无规则圆角混用。

### 12.2 功能

- 原有团队列表加载、搜索、分页和跳转不回退。
- 创建团队、查看团队等主要入口可用。
- 登录和未登录状态均有正确反馈。
- 空数据、加载失败和无搜索结果有独立状态。

### 12.3 响应式

至少验证以下视口：

- `1440 × 900`
- `1280 × 720`
- `1024 × 768`
- `768 × 1024`
- `390 × 844`

不得出现：

- 页面横向溢出。
- 按钮或文字被无提示截断。
- 工具栏遮挡内容。
- 双栏内容互相挤压。
- 移动端触控区域过小。

### 12.4 工程质量

- 新组件职责清晰，无重复页面级实现。
- 新样式全部在团队首页命名空间内。
- 没有新增无用途的全局状态。
- lint 和生产构建通过。
- 关键首页交互具备适量测试或可重复的人工验收步骤。

## 13. 开发前待确认项

以下内容在正式实现前需要结合产品需求确认，但不影响先建立页面骨架：

- 首页频道最终包含哪些项目。
- 右侧辅助区首期展示哪些数据。
- “创建团队”是否作为唯一主操作。
- 首页默认服务器来自用户角色、缓存还是全局默认值。
- 团队列表首期是否同时展示活动和招募摘要。
- 移动端是否需要独立路由组件。

没有确认的功能不得通过假数据伪装为已接入功能；可以先保留结构插槽或隐藏对应区块。

## 15. 当前风格总结

当前团队首页的风格可以概括为：

> 轻量、清晰、克制的团队发现工作台。

它不沿用传统后台的固定全局侧栏，而是在首页工作区内使用轻量个人工作台与右侧发现区形成主次关系。浅灰页面背景、白色内容表面和低对比度边框建立层级；紫蓝色只用于主操作、选中和焦点状态，团队 Logo、认证、勋章等业务信息保留自身语义色。

页面强调“先找团队，再管理团队”的使用路径：

1. 左侧个人工作台先提供导航和已加入团队的直接入口。
2. Hero 说明页面身份并提供创建团队与使用指南。
3. 工具面板集中服务器、搜索和类型筛选。
4. 双列团队卡片提高宽屏信息密度。
5. 响应式布局保证窄屏阅读顺序。
6. 骨架屏和稳定分页减少刷新、搜索及翻页时的布局跳动。

后续新增团队首页功能时，应优先沿用现有设计令牌、圆角层级、标签样式和加载策略，避免重新引入厚重侧栏、强阴影、无规则色彩或重复的点击提示图标。
